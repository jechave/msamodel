## 4. Code refactoring rules (minimal changes, "stay close to current code")

When copying a file from `tmp_src/R/` to `msamodel/R/`:

1. **Remove `library(...)` calls** (inline and top-level). All package usage goes
   through `Imports:` + `@importFrom` (or `pkg::fn()`). Verified locations of
   inline `library()` in the migrated files (this supersedes the earlier,
   partly-wrong inventory):
   - `msa_allotment.R:63` `library(dplyr)`, `:99` `library(tidyr)` — strip.
   - `protein_msa_allotment.R:75` `library(dplyr)`, `:109` `library(tidyr)`, `:110` `library(dplyr)` — strip.
   - `compare_loess_fits.R:163` `library(ggplot2)` — strip (see rule 8 re: ggplot).
   - `protein_msa_decomposition.R` — **none** (no inline `library()`; earlier claim was wrong).
2. **Namespacing — Option A (default):** add a package-level `@importFrom` for
   each tidyverse function used and keep the bare calls (smallest diff). Do not
   qualify every call inline.
   - **Exception (Suggested packages):** `@importFrom` is illegal for a package
     in `Suggests:`. The only case is **ggplot2** in `loess_compare.R`
     (`plot_loess_comparison`). There, qualify calls as `ggplot2::geom_point()`
     etc., behind the existing `requireNamespace("ggplot2")` guard. (This
     function is unexported in v0.1 — see rule 8 — so the issue is contained to
     one file.)
3. **Keep function signatures identical.** Do not rename functions or variables
   or "improve" logic. This is a migration, not a refactor.
4. **Keep `%>%`** (magrittr, re-exported).
5. **`here::here(...)`** — none appear in `R/` (confirmed); nothing to do.
6. **Strip the non-standard `@requires` roxygen tags.** Every source file uses a
   homegrown `@requires Functions:` / `@requires Packages:` convention that
   roxygen2 does not recognise (it will warn). Delete these lines. If the
   dependency info is worth keeping, move it to prose or `@seealso`. Keep all
   standard tags (`@param`, `@return`, etc.) as-is.
7. **Fix the catalogued bugs** as you reach each file (see §11): delete the
   duplicate `define_selection_grid` (`msa_a1a2grid_workflow.R:106-119`, keep the
   one at line 60); fix the `"lower,Quite upper"` roxygen typo
   (`msa_bayesian_analysis.R:205`).
8. **Add `@export`** to every top-level function in the export list (§6); helpers
   stay unexported (`#' @noRd`).
   - **`plot_loess_comparison` is NOT exported in v0.1** (decided 2026-06-04). It
     hard-depends on ggplot2 (a Suggested package) and belongs with the deferred
     visualization module (v0.3). Keep it in `loess_compare.R` as an internal
     (`@noRd`), or omit it. Either way it is not part of the public API, so the
     export count drops by one (see §6).

## 5. Embedded data preparation (`data-raw/prepare_znb_data.R`)

The script **reads from the source project** (read-only) and writes `.rda` files to `msamodel/data/`. It does not modify the source.

Pseudocode:
```r
# data-raw/prepare_znb_data.R
library(here)          # here() resolves to the msamodel package root
library(bio3d)
library(penm)
library(dplyr)
library(readr)

# During migration, read from the frozen snapshot:
SRC <- here::here("tmp_src")
# NOTE: tmp_src/ is deleted after migration. Before then, if this script must
# survive (it re-generates the embedded data), repoint SRC at the canonical
# live project:
#   "/Users/julianechave/Library/Mobile Documents/com~apple~CloudDocs/lab/projects/MSA-neutral-structure-evolution"
pdb_chain <- "1znb_A"

# 1. Copy raw PDB to inst/extdata (not a dataset, used by examples)
file.copy(
  file.path(SRC, "data", "pdb_chain", paste1(pdb_chain, ".pdb")),
  here("inst", "extdata", paste0(pdb_chain, ".pdb")),
  overwrite = TRUE
)

# 2. znb_pdb: raw bio3d object
znb_pdb <- bio3d::read.pdb(here("inst", "extdata", "1znb_A.pdb"))

# 3. znb_wt: penm ENM wild-type
znb_wt <- penm::set_enm(znb_pdb, node = "ca", model = "ming_wall",
                        d_max = 10.5, frustrated = FALSE)

# 4. znb_spm: copy precomputed SPM
znb_spm <- readRDS(file.path(SRC, "data", "spm", paste0(pdb_chain, "_spm.rds")))

# 5. znb_profile: extract from profiles_ec2024.csv
profiles <- readr::read_csv(
  file.path(SRC, "data_input", "profiles_ec2024.csv"),
  col_types = readr::cols(site = readr::col_integer())
)
znb_profile <- profiles |>
  dplyr::filter(pdb_chain == !!pdb_chain) |>
  dplyr::transmute(i = site, lrmsd_obs = lrmsd, dactive, lrmsf)

# 6. znb_dataset: 1-row active-site info
dataset <- readr::read_csv(
  file.path(SRC, "data_input", "dataset_ec2024.csv"),
  col_types = readr::cols(.default = readr::col_character())
)
znb_dataset <- dplyr::filter(dataset, pdb_chain == !!pdb_chain)

# 7. Save all as .rda
usethis::use_data(znb_pdb, znb_wt, znb_spm, znb_profile, znb_dataset,
                  overwrite = TRUE, compress = "xz")
```

**Parameter recording (required for `test-spm-generate.R`):** the parameters passed to `setup_enm()` and `generate_spm_data()` in this script MUST match the ones the test uses to regenerate `znb_wt`/`znb_spm`. Two options:
- (a) Hard-code the same values in both files, with a comment cross-referencing the other.
- (b) Store them as attributes on the saved objects (`attr(znb_wt, "build_params") <- list(...)`) and have the test read them back.

Pick (a) unless attributes are clearly better. Either way: the test must not silently pass when parameters drift.

Also note the `paste0` typo (`paste1`) in the pseudocode above — fix when writing the real script.

`data-raw/source_files.txt` — manifest of what was copied, so the provenance is trackable:
```
1znb_A.pdb        ← <SRC>/data/pdb_chain/1znb_A.pdb
znb_spm           ← <SRC>/data/spm/1znb_A_spm.rds
znb_profile       ← <SRC>/data_input/profiles_ec2024.csv (filtered pdb_chain==1znb_A)
znb_dataset       ← <SRC>/data_input/dataset_ec2024.csv (filtered pdb_chain==1znb_A)
```
